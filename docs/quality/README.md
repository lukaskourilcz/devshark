# Developer quality tools

These checks run on the existing Vite, Astryx, TanStack Query and PostHog stack. None needs a paid service, a production mock server or another UI system.

| Area | Run / entry point | What it checks or changes |

The system-font first visit downloads no font files; OG generation keeps its separate build-time fonts. |

## Install and CI

Use Node 24, `npm ci` and `npm ci --prefix client`, then install Chromium once with `npx playwright install chromium` for browser and Lighthouse work. In the Claude Code cloud environment the browser is preinstalled under `/opt/pw-browsers` and `npx playwright install` is disabled: set `CHROME_BIN=/opt/pw-browsers/chromium` (and `CHROME_PATH` for Lighthouse), because the preinstalled build is not the one Playwright 1.63 would download. `CHROME_BIN` and `CHROME_PATH` can point to any compatible browser. After a build, start `npm run preview --prefix client -- --host 0.0.0.0 --port 4173`.

The Product quality workflow (`.github/workflows/quality.yml`) has the jobs `sql`, `quickjs`, `client-build`, `static`, `tests`, `coding`, `browser` and `container`, plus `verify`, which passes only when the seven non-SQL jobs pass. Branch protection requires `verify` and `sql`. The shared client-build job builds devShark once and packages all output, including hidden manifests and source maps. Static and browser jobs verify the artifact head and file hashes. The browser job runs the explicit Playwright selection in one two-worker invocation, the responsive checks in both themes and the harness test, then builds Storybook and records Lighthouse results; reports go up as the `quality` artifact. `npm run ci:parity` runs the same jobs locally (`--list`, `--only`, `--fast`). The Vercel Git integration owns deployment; the workflow deploys nothing.

Do not add MSW initialization to `src/main.tsx` or copy its worker into `client/public`: the worker lives only in `client/.storybook/public`. The workshop's own Vite config keeps app build hooks away from Storybook output and clears service credentials. Browser tests that need Storybook skip unless `STORYBOOK_URL` is set; the workflow sets it in a separate step.

## Knip

`check:unused` rejects new findings and stale reviewed-baseline entries. Value exports in `lib/` and `shared/` must have actual readers or a source-documented `@public` contract for a concrete dynamic-test, authoring or package API. Client exports and type-only exports remain advisory. The F14 cleanup leaves the reviewed baseline empty and adds no path ignores. Check actual readers before changing a documented contract.

Knip reads the Storybook configuration and scans the Vercel handlers, nested maintenance scripts, Docker sources, isolated sandbox, stories and tests. Its Vite plugin is disabled because the build configuration imports a TSX renderer. The explicit dependency exceptions are the Astryx CSS theme and the Lighthouse executable. The development environment supplies `vercel` and `psql`. The preview-access fixture uses the system’s `mkfifo` command to create a named pipe.

## SEO and deployment

Guides live at `/topics/:slug`. React renders the same `TopicArticle` the build prerenders. They are public explanations and examples, never scored-session answers. Static topic rewrites precede the SPA fallback. An unknown static guide resolves to a missing file on Vercel, and an unknown guide rendered in the client carries `noindex`. Leaving a guide clears its metadata, so a quiz never inherits a guide's canonical URL or schema.

The canonical origin is the production domain in `client/src/lib/publicMetadata.ts`, never a request host or a preview URL; if the domain changes, update it and rebuild. LearningResource describes what the page contains and promises no rich result. Submitting the sitemap in Search Console is an owner action outside the deployment.

## Reading the measurements

Lighthouse is lab evidence for one run, not field Core Web Vitals or a promise about conversion. Keep the complete JSON and HTML reports, and compare runs of the same product, route, device profile and build configuration. The bundle check leaves out lazy routes, font files and the coding sandbox; Lighthouse and the treemap show their cost.

`npm run check:bundle` builds its own copy of the client into `client/dist-budget` (removed after the run) with the build-time variables production sets, then gzips the entry script, the modulepreload links and the stylesheets that `index.html` requests. Client code depends on those variables: without the Supabase pair, a build leaves out code production serves. `docs/quality/bundle-budget.json` lists them under `measuredBuild.env`, as placeholders with the real values' length and alphabet, and the check prints which configuration it measured. Add a variable there when client code starts to depend on a new one. CI's main build reads the Supabase pair from the same file, so the browser checks run against a build that signs in the way production does.

The 24 November dependency follow-up measured **215,975 gzip bytes**. With the private Play changes and the remaining three Play labels in the lazy route, the four initial files measure **215,968 gzip bytes**, which is the new `initialGzipBytes` cap. The preceding audited build measured 217,717 bytes. Both loaded one entry script, two JavaScript modulepreloads and a stylesheet. F3 (#632, PR #666) measured four initial requests at its previous ceiling of 218,675 gzip bytes on 19 November 2026, against the comparable production-shaped main `0f35d67d` baseline of 235,485 with identical public build placeholders. F3's entry CSS fell from 25,843 to 24,779 gzip bytes. The subsequent F14 runtime checkpoint `be426ec4` measures **218,580 gzip bytes**, leaving 95 bytes below the same cap; its rich mobile-menu content CSS loads with the lazy renderer while the loading/error frame stays global. These are separate measured checkpoints. React/Router and TanStack remain the two useful modulepreloads, down from three before the vendor groups combined. The ten-largest-chunks report also includes lazy chunks; those are not extra initial requests.

The first visit previously preloaded 73,092 bytes of Manrope and Inter although the active design uses system fonts and emitted no font-face rule. It now preloads no fonts. The browser regression checks the requested chunks' source maps, including dynamic requests, for Motion, editor, rich-text, highlighting, QR, PostHog and Supabase packages. Drawer and toast animations load on use; the drawer closes at the 1024px desktop boundary without retaining hidden focus or replaying a pending request. Account-track synchronization keys on account id and the validated track rather than user-object identity. The eager hosts keep focus, live regions and XP events usable while code loads or fails. The route fade uses CSS. Account, Shop, Terms and lesson figure styles load with their components; public guides retain their no-JavaScript styles.

The check also measures the Sentry SDK against `monitoringGzipBytes` (60,000). It fell from 49,565 to 46,800 gzip bytes after production debug branches were disabled; tracing stays enabled at its existing 0.1 sample rate. This is not an initial request: it loads after the page's load event, at the browser's next idle moment, or on the first error. `lib/supabaseClient.ts` loads `@supabase/supabase-js` on demand, as a lazy `supabase-*.js` chunk of about 55 kB gzipped. A visitor downloads it when a session is stored (a returning, signed-in learner, whose requests meanwhile carry the stored token while it is more than 90 seconds from expiry, and whose public reads carry none), when the URL carries an OAuth return, on a sign-in click, or when another open tab signs in; a visitor who never signs in never downloads it, and `tests/browser/lazy-auth.spec.ts` checks both sides. A second chunk of about 400 gzip bytes, the app's own `lib/supabase.ts` API helpers, also starts with `supabase-`. It is not an initial request: the lazy chunks that call the API load it, among them Learn, Quiz, the Challenge, Today, Profile, the leaderboard, Cards and the coding pages.

Never remove sandbox isolation or development React from the exercise frame to improve the main application's score.

## Bundle, route and asset measurements

The [Epic F baseline index](../audit/epic-f-baseline-2026-11.md) links the actual dated artifacts and their source, build and request scopes. Missing original or production measurements remain explicit.

`npm run check:bundle` builds with the public placeholders in `bundle-budget.json`, applies the 215,968-byte initial gzip budget and lists the ten largest chunks separately. `--largest=20` expands that list. `ANALYZE=true npm run check:bundle` also writes the matching treemap and module report under `client/dist/`; an arbitrary `npm run build` can have a different environment and graph. Lazy chunks are not initial bytes, and module gzip estimates do not add up to whole-file gzip.

`npm run check:bundle -- --url="$MEASUREMENT_ORIGIN"` explicitly selects a separate anonymous HTTP observation and skips the build/budget gate. Supply one bare HTTPS origin or an HTTP loopback origin. It follows only the document's same-origin `/assets/` entry, modulepreload, stylesheet and font links, with at most 33 GETs, no redirects, retries, cookies or authorization. `artifacts/bundle-live.json` separates encoded response-body bytes from decoded bytes and reconstructed gzip6. These counts exclude headers and transport overhead; they are not a browser waterfall or recursive CSS/dynamic-import graph. Failures retain a partial report with unknown values. Use owned loopback fixtures unless a counted external measurement is authorized.

For per-route Lighthouse, start a local preview of the production-shaped build, then run `npm run audit:performance -- --url=http://127.0.0.1:4173 --routes=/,/learn --runs=3 --output=artifacts/performance/routes`. This writes each mobile/desktop sample and median/min/max summaries. Record route state: a static preview has no live API, so a data route may show an error or signed-out state. Lighthouse navigation mode supplies no field INP.

`npm run perf:measure -- --url=http://127.0.0.1:4173 --routes=/,/learn --samples=3 --profiles=mobile,desktop --fixture --output=artifacts/performance/routes-cdp.json` records cold undecided and repeat rejected-consent loads with one scripted interaction per load. When measuring an older build, use `--consent-version=<n>` with the version its consent module accepts. A rejected repeat visit that still shows the consent banner is excluded from summaries and the command exits with an error. `--fixture` supplies settings and explicit 503 responses for other API reads. To measure populated data routes, add `--api-origin=http://127.0.0.1:4181` backed by an owned, documented fixture corpus. Only the existing anonymous read allow-list is copied, once per distinct read; writes remain blocked. Neither the synthetic delay nor those bodies represent production data or latency. Record request totals, failed rows, actual interactions and source/build/browser versions. Use a quiet machine and label comparisons across different builds or states. Ready Daily uses local radio selection without checking or submitting the answer; question focus mode hides the menu/theme controls. Missing or unregistered input makes the completed collection exit nonzero while retaining valid paint metrics. The consentBanner field records DOM presence, which can remain true for a visually hidden banner.

`node scripts/audit-image-inventory.mjs --output=docs/audit/image-inventory-YYYY-MM.json` inventories every regular source asset, including non-image files. Optional `--dist-dir=client/dist` adds a separate built-image scope. Rows carry byte/hash/format data, strict intrinsic metadata or an explicit unknown/error, and lexical source/reference hints. A source width hint is not a rendered size; a missing literal reference is not deletion evidence. Symlinks are skipped or refused, and the explicit atomic output cannot alias source or an unrelated file. Freeze source, run twice and compare bytes. `npm run check:images` remains the independent release gate with its raster and share-image caps.

## Server entry measurements

`npm run perf:cold-start -- --url="$PREVIEW_URL" --output=artifacts/performance/entries.json` requires PREVIEW_URL to name the exact bare Preview origin and sends three serial GETs to each of the twelve physical handlers. The fixed manifest selects five public reads and seven refusal branches. It avoids normal quiz/Daily/Challenge issuance, wallet settlement, coding sessions and grading. The default is 36 requests, with 1,100 ms spacing, a 15-second deadline and a one MiB response bound. HTTP 429 stops the remaining plan. The command follows no redirect and retries no request.

For a protected Preview, add `--preview-state=/absolute/path/to/approved-state.json`. Reuse an authorized frontdoor cookie with one exact deployment host, owner-only file access and no application login; the collector neither obtains access nor exchanges a share link. It validates the file before any request and refuses output paths that alias it. Never commit, print or upload that state. A state for one Preview cannot authorize another host or production. Do not create an automation secret or change protection to run a check.

The report separates socket/DNS/TLS/first-byte offsets from the origin app and Supabase transport spans. Concurrent transport durations can exceed the app span. CDN HIT/STALE timings are replays. The optional first/repeat value marks the first call through a timing-module instance and appears only with explicit nonshared no-store caching. Public requests consume the first call but expose no marker; missing/cache-unknown evidence stays unknown. None of these fields measures platform initialization, a unique instance count or a platform cold boot. Refusal timing does not measure grading.

`npm run perf:cold-start -- --local --markers --output=artifacts/performance/imports.json` compiles the same twelve entry files as instrumented CJS with locked esbuild and external packages, then requires each in three fresh Node children. It records import wall time, CPU, unforced-GC heap differences, package/module markers and artifact bytes. It invokes no handler, supplies no deployment credentials and denies the covered transports/process paths before import. This local proxy is not a Vercel deployment artifact, hostile-code sandbox, retained-memory measurement or server operation benchmark. Keep the Node/compiler/lock/tool/source hashes with both sides of a comparison, retain all twelve rows and report overlapping or slower results.

`npm run test:performance` includes the collector safety fixtures, actual public validators, roadmap concern boundaries, representative upstream counts and connection-reuse controls. Server-Timing counts Supabase REST/Auth transports; it does not count Upstash. The ten-operation fixture records those transports, Upstash commands and sequential waves separately. Its first/repeat-cache table describes named invented scenarios rather than the ten most frequent production operations. Conditional responses save body bytes after the normal access/rate checks and reads, so they do not prove fewer upstream calls.
